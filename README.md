# CANTool — 自定义 CAN 报文发送工具

Windows 下的 CAN 报文收发与发送工具，界面参照 CANTest 布局，支持完全自定义的报文内容、
批量发送和多路定时（周期）发送。底层对接周立功 ZLG USBCAN 系列（`zlgcan.dll`）。

## 功能

| 区域 | 能力 |
| --- | --- |
| 设备连接 | 接口选择（ZLG USBCAN / 仿真回环）、设备类型、索引、通道、波特率（10 档 + 自定义 Timing0/Timing1）、正常/只听模式、验收滤波 AccCode/AccMask、打开/复位/清空缓冲 |
| 报文发送 | 帧格式（标准/扩展）、帧类型（数据/远程）、发送类型（正常/单次/自发自收/单次自发自收）、ID、DLC、8 个数据字节单独输入；单发、批量 N 次、勾选后按周期自动发送、一键加入列表 |
| 列表发送 | 表格内直接编辑多条报文；新增/插入/删除/清空；导入导出 CSV 或 JSON；发送选中、全部发送；一键启动/停止所有勾选行的定时发送；右键菜单可对单行启停定时；实时显示每行已发帧数 |
| 报文显示 | 收发合流表格（序号、时间、方向、帧格式、帧类型、ID、长度、数据、设备时间戳），发送蓝色、错误帧红色；暂停、清空、导出 CSV、自动滚动、按方向过滤、按 ID 过滤（多个用逗号分隔）、容量上限与滚动丢弃 |
| 信号实验 | 17 路物理信号垂直滑杆（启用复选 + 单位 + 数值/状态编辑器），按 `signals.json` 的映射把物理值打包成报文周期发送；滑杆改动实时热更新已启动的报文；实验工况可命名保存/载入（`experiments.json`）；映射配置对话框可改 CAN ID、起始字节、长度、字节序、系数/偏移 |
| 状态栏 | 累计发送 / 接收 / 错误帧计数，通道 TEC/REC 与 BUS OFF 提示 |

所有收发都在后台线程完成，界面不会因总线繁忙或设备无响应而卡死；定时发送按单调时钟
调度，错过的周期直接跳过，不会积压后爆发式补发。

## 环境

- Windows 10/11，64 位
- Python 3.10+（开发环境为 3.11.5 64 位）
- PySide6

```bash
pip install -r requirements.txt
```

`lib/` 目录已包含 ZLG 官方 `zlgcan.dll` 与 `kerneldlls/`（x64），无需另外安装 SDK。
设备本身需要安装周立功的 USB 驱动。

## 启动

```bash
python main.py          # 正常启动
python main.py --sim    # 启动后默认选中"仿真回环"，没有硬件时验证界面与流程
```

也可以直接双击 `启动.bat`。

## 使用流程

1. **设备连接** 里选接口、设备类型、索引、通道和波特率，点 **打开设备**。
   成功后指示灯变绿，状态栏显示设备型号与序列号。
2. 在 **报文发送** 区填 ID 与数据，点 **发送** 发一帧；填 **批量次数** 后点 **批量发送**
   连续发 N 帧；勾选 **定时自动发送** 则按设定周期持续发送，取消勾选即停止。
3. 需要多路并发时，用 **加入列表** 或 **新增** 把报文放进 **列表发送** 表格，
   为每行设置 `周期(ms)` 与 `次数`（0 = 无限），点 **开始定时** 一次性启动所有勾选行。
4. **报文显示** 区实时滚动收发记录，可暂停、过滤、导出 CSV。
5. 用完点 **关闭设备**。退出程序时若仍有定时发送在跑会二次确认。

### 信号实验（滑杆发报文）

切到 **信号实验** 选项卡：每路信号一列垂直滑杆，勾选启用后其物理值会按映射装进
对应 CAN 报文；点 **开始** 后按设定周期持续发送，拖动滑杆或切换状态会实时改写正在
发送的报文内容，点 **停止** 结束。

- 底部编辑器分两种：**数值**（与滑杆联动的数字输入）和 **状态**（如 正常/故障/开路/短路，
  选中非"正常"状态时发送该状态的固定原始值，滑杆变灰）。
- 顶栏 **添加实验** 把当前所有滑杆/状态/启用状态按名称存进 `experiments.json`，
  之后可从下拉框一键载入复现工况。
- **映射配置** 对话框编辑每路信号的报文映射（CAN ID、扩展帧、起始字节、长度 8/16/32、
  Intel/Motorola 字节序、系数、偏移、编辑器类型、状态原始值），保存为 `signals.json`。
  换算关系：`物理值 = 原始值 × 系数 + 偏移`。
- **注意：内置的 17 路信号（转速/扭矩/车速/DPF温度/…/排气流量）只保证界面与参考工具一致，
  默认报文映射（0x100~0x104、每信号 16 bit）是占位值**，上车前必须按实际协议
  （DBC 或协议文档）在映射配置里改正。

### 列表发送模式

- 并行发送：勾选的报文各自按本行周期发送，本行次数为 0 时无限发送。
- 顺序循环发送：勾选的报文按列表从上到下发送。同一轮相邻报文使用“报文间隔”，本轮末条到下一轮首条使用“列表间隔”，两者独立设置，不叠加。循环次数为 0 表示无限；表格中的周期和行次数在此模式下禁用。
- 并行模式所有启用行的周期必须大于 0。开始时立即发送首行；发送期间锁定列表和模式，停止或发送完成后恢复编辑。
- 顺序循环高亮当前行，不显示轮次和条数文字。有限循环在最后一行发送后完成。

## 报文列表文件格式

导出/导入支持 `.csv`（带 BOM，Excel 可直接打开）和 `.json`。

CSV 示例：

```csv
启用,备注,ID(hex),帧格式,帧类型,发送类型,长度,数据(hex),周期(ms),次数
1,发动机转速请求,7E0,标准帧,数据帧,正常发送,8,02 01 0C 00 00 00 00 00,100,0
1,故障码注入,18EFEE00,扩展帧,数据帧,自发自收,8,FF 22 F8 0B FF FF FF FF,200,50
```

JSON 示例：

```json
{
  "version": 1,
  "messages": [
    {"enabled": true, "note": "发动机转速请求", "id": "7E0", "extended": false,
     "remote": false, "send_type": 0, "dlc": 8,
     "data": "02 01 0C 00 00 00 00 00", "period_ms": 100, "repeat": 0}
  ]
}
```

字段说明：`send_type` 0=正常发送 1=单次发送 2=自发自收 3=单次自发自收；
`repeat`/`次数` 为 0 表示无限；`data` 支持 `01 02`、`01,02`、`1 2`、`0102AB` 等写法。

## 实用提示

- **总线上没有其它节点时，"正常发送"会因为没有 ACK 而失败**（提示"请求 N 帧，实际发出 0 帧"）。
  这是 CAN 的正常行为，不是程序故障。此时把发送类型改成 **自发自收**，或接上被测 ECU、
  并确认波特率与终端电阻正确。
- 波特率对应的 Timing0/Timing1 已内置 1000k~5k 共 10 档；选 **自定义…** 可手工填写寄存器值。
- 只想监听不想干扰总线时，把工作模式设为 **只听模式**。
- 界面参数（设备配置、日志容量、窗口位置）保存在 `settings.json`，下次启动自动恢复。

## 已知限制

- 仅支持经典 CAN 2.0A/B。CANFD 设备（USBCANFD-200U/100U/MINI 等）需要走
  `ZCAN_TransmitFD` 与 abit/dbit 时序配置，当前未实现，因此设备类型下拉里不包含它们。
- CANET/WIFICAN 等网络设备需要通过 IProperty 配置 IP，当前未实现。
- SDK 自带的虚拟设备（类型 99）实测 `ZCAN_Receive` 恒返回 0、`GetReceiveNum` 恒返回 20，
  不可用；因此无硬件调试请使用本工具内置的 **仿真回环** 后端（发出的帧原样回到接收区）。
- 定时精度约 ±2 ms，适合 ≥10 ms 的周期；毫秒级以下的严格实时发送应改用设备的
  自动发送对象（`ZCAN_AUTO_TRANSMIT_OBJ`）。

## 打包成 exe

```bash
pip install pyinstaller
pyinstaller -w -n CANTool main.py --add-data "lib;zlgcan.dll" --add-data "lib/kerneldlls;kerneldlls"
```

打包后需保证 `lib/zlgcan.dll` 与 `lib/kerneldlls/` 与可执行文件的相对位置不变。

## 安全提示

本工具会向真实 CAN 总线注入报文。连接到车辆或在用设备前，请确认已获得授权，
并核对 ID 与数据内容——错误的报文可能触发 ECU 故障保护或影响行车安全。
